# Перевірка експериментальної збірки Chrome / Edge — 24 вересня 2026

[English](VERIFICATION.md) · [Українська](VERIFICATION.uk.md)

Це українська карта стану перевірок. Повні команди, журнали попередніх версій і
історичні результати збережені в канонічному [англійському журналі](VERIFICATION.md).
Статус не можна підвищувати лише на підставі цієї коротшої локалізації.

## 0.9.3 — ручна перевірка Chrome зі слів власника

24 вересня 2026 року після ручного списку перевірок Chrome власник повідомив:
«все працює, лок блокує обох, імпорт експорт ок». Явно підтверджено **Lock для
двох панелей** і **роботу імпорту/експорту**. Це успішний результат ручної
перевірки встановленого кандидата 0.9.3 зі слів власника, а не незалежно
спостережений чи автоматизований результат.

Точну версію Chrome, операційну систему й тип експорту не зазначено.
Загальне підтвердження не є окремим записом результату кожного рядка матриці.
Приймання поточного Edge-пакета, встановлення з магазину та оновлення
перевіряються окремо; цей звіт їх не підтверджує.

## 0.9.3 — підготовка до Chrome Web Store

Із маніфесту прибрано зайвий `activeTab`; захоплення сторінки й далі запитує
необов’язковий доступ до сайту перед `scripting.executeScript`. Політику приватності
доповнено заявою про Chrome Limited Use. Runtime-код і версії спільного редактора
не змінено. Ця зміна дозволу й документації не підтверджує перевірки встановленого
пакета Chrome/Edge або подання до магазину.

Пройшли 34 наявні цільові тести конфігурації збірки, пакування, адаптера браузера,
авторизації сервісу й дій панелі. Тести із запуском дочірнього Node повторено
поза пісочницею після блокування процесів її обмеженнями; помилок продукту
не залишилося.

## 0.9.2 — перевірка акордеонів та індикації збереження

- Узгоджені версії: Standard Notes **46.0.2**, AIC Notes **54.0.2**, спільне ядро
  **7.3.2**. Формат сховища браузера й дозволи не змінено.
- CUA-перевірка в Chromium використовувала синтетичну нотатку зі справжнім
  `AicEditor` — спільним редактором Standard Notes і браузера. Світлу й темну
  теми перевірено на ширинах 360 і 1280 px. Вкладені код, Mermaid і таблиці
  зберігали відступи та межі акордеона без горизонтального переповнення всього
  документа. Режим читання залишався захищеним.
- Зібраний production webview VS Code перевірено із синтетичним хостом у
  головному редакторі та Linked Note. У темному Linked Note натискання checkbox
  створювало незбережену зміну, але фон редактора лишався `rgb(24, 26, 28)`,
  а колір тексту не змінювався. Кнопка Save помітно пульсувала; синтетичне
  підтвердження збереження приховувало її.
- Згортання акордеона приховувало весь його вміст. Редагування вкладеного коду
  відкривало джерело лише цього блоку.
- Це перевірки інтерфейсу із синтетичним хостом, а не перевірка транспорту
  Standard Notes, встановленого розширення браузера чи фізичного пристрою.
  Повні релізні перевірки та перевірки фінальних файлів фіксуються окремо;
  попередні результати нижче не підтверджують приймання встановлених пакетів
  Chrome/Edge версії 0.9.2.

## 0.9.1 — перевірка вузьких панелей записів

- Узгоджені версії: Standard Notes **45.0.1**, браузер **0.9.1**, AIC Notes
  **53.0.1**, спільне ядро **7.3.1**. Формат сховища браузера не змінено.
- Область перевірки: генерація в порожніх полях на вузьких екранах, перенесення
  параметрів, збереження заповнених значень і відсутність дії в режимі читання.
- Генератор канонічного редактора перевірено із синтетичними даними та CSS для
  сенсорного вводу на ширинах 240, 320, 360, 600 і 601 px, зокрема в темній темі
  на 360 px. Він залишався видимим і в межах панелі. Генерація дала замасковану
  кнопку із замком, прибрала дію генерації із заповненого поля та зберегла
  сусіднє значення.
- Зібраний production webview VS Code перевірено із синтетичним хостом: головний
  редактор у світлій темі та Linked Note у темній на 360 px, а також головний
  редактор у світлій темі на 320 і 240 px. Горизонтального переповнення не було;
  заголовки груп мали розмір 16 px і насиченість 750, нейтральний фон відокремлював
  групи та рядки, панель генератора вміщувалася на 240 px.
- На 360 px у темній темі копіювання пароля змінювало замок → галочку → замок,
  зберігаючи точний розмір 44 × 44 px і доступне повідомлення про стан.
  Відповіді буфера обміну були синтетичними; системний буфер не використовувався.
- Це перевірки інтерфейсу канонічного редактора та зібраного VS Code webview із
  синтетичним хостом. Вони не підтверджують приймання встановленого розширення
  браузера, Standard Notes з авторизацією або фізичного мобільного пристрою.

## 0.9.0 — область перевірки перенесення та сортування

- Узгоджені версії: Standard Notes **44.1.0**, браузер **0.9.0**, AIC Notes
  **52.1.0**, спільне ядро **7.3.0**. Формат сховища браузера не змінено.
- Контракт перевіряє перенесення полів природної ширини, копіювання пароля
  кнопкою із замком, стабільне сортування при виході з джерела та збереження значень.
- Перевірка справжнього редактора у вбудованому Chromium на ширинах 320, 360,
  393 і 768 px не виявила переповнення рядків або сторінки у світлій, темній
  темах та режимі читання. Синтетична перевірка CSS для сенсорних пристроїв
  підтвердила висоту кнопок назв і розмір замків 44 px; фізичний пристрій не
  емулювався.
- Зібрані основний редактор VS Code та Linked Note перевірені із синтетичним
  хостом на вузьких ширинах в обох темах. Підтверджені відгук копіювання,
  сортування після редагування та негайне приховування секретів, без видимих
  помилок. Справжні нотатки й системний буфер не використовувалися. Файл
  `test/fixtures/security-layout.html` зберігає синтетичний приклад для повторної
  візуальної перевірки.
- Перевірки вузької ширини використовують синтетичні дані. Фізичні мобільні
  пристрої та встановлені Standard Notes/Chrome/Edge з обліковими даними
  потребують окремого приймання; цей запис не стверджує, що його вже виконано.

## 0.6.0 — Mermaid: код і прев’ю

- Канонічний редактор спрощено до Markdown-коду та живого прев’ю.
- У прев’ю лишилися Copy, одна іконка Edit і масштабування.
- Візуальний конструктор, drag-and-drop та поворот видалені.
- Синтетичний Chromium regression пройшов для вузької панелі, flowchart,
  Copy/Edit, zoom і живого оновлення.
- `npm run check` та `npm run build:browser` пройшли на Ubuntu й Windows у
  релізному workflow.
- Опублікований ZIP має кореневий `manifest.json`, проходить ZIP integrity check,
  а SHA-256 збігається з sidecar-файлом.

Ці результати доводять структуру і синтетичну поведінку пакета. Вони ще не є
підтвердженням публікації в Chrome Web Store або Edge Add-ons і не замінюють
ручну перевірку встановленої магазинної збірки.

## Попередні перевірені зміни

### 0.5.2

Інформаційні (`>`), warning (`!>`) та error (`!>>`) цитати мають різні акценти,
легкий фон і менший текст; `>>> … <<<` лишається details. Незавершений
три-backtick fence не ховає джерело, готовий блок відкриває прев’ю після focus
out.

### 0.5.1

Заголовки, цитати й списки мають більші відступи. `---` показується як
центрована лінія 50–100 px із простором згори й знизу; висота рядка не змінюється,
коли під курсором видно сирий Markdown.

### 0.5.0

Панель стискається без фіксованої мінімальної ширини. Назви й значення поля
переносяться разом. Новий AIC-блок починається порожнім текстовим рядком, Account
preset прибраний, Password і TOTP окремі. Генерація пароля прихована на ширині
600 px або менше.

### 0.4.0

Global Shared зберігається як один зашифрований запис профілю, незалежний від
Domain і Page. Copy section створює окремий `aic`-блок без зміни джерела.
Library v3 читає v1/v2, а downgrade після нового запису потребує попередньої
резервної копії.

## Матриця приймання runtime

Перед production-розповсюдженням потрібно перевірити поточний пакет окремо
в **Chrome та Edge** й записати результати:

| Перевірка          | Очікування                                                    |
| ------------------ | ------------------------------------------------------------- |
| Чисте встановлення | Панель запускається з unpacked або store package без помилок  |
| Контекст вікна     | Панель слідує лише за активною вкладкою свого вікна           |
| Private mode       | Incognito/InPrivate недоступні згідно з маніфестом            |
| Дозвіл capture     | Доступ до origin запитується лише після явного імпорту        |
| Save/reopen        | Підтверджена нотатка відновлюється після повторного відкриття |
| Session/restart    | Lock/restart/update прибирає сесійний ключ                    |
| Clipboard          | Реальні Copy/Paste працюють лише після явної дії користувача  |
| Lock між панелями  | Lock прибирає відкритий вміст і сесійний ключ у всіх панелях  |
| Дані на диску      | `storage.local` містить ciphertext, а не ключ або Markdown    |
| Network denial     | CSP не дозволяє вихідні fetch/XHR/remote embeds               |
| Backup             | Зашифрований export відновлюється лише з правильним паролем   |
| Conflict           | Програна зміна лишається чернеткою для retry/export           |
| Narrow UI          | Поля читабельні без окремого values-only scroll               |
| Mermaid            | Source, live preview, Copy/Edit і preview zoom стабільні      |

Для кожного браузера треба зафіксувати точну версію, ОС, спосіб встановлення,
профіль, результат і відомі обмеження. Edge-перевірка не доводить Chrome і
навпаки. Реальні clipboard і запити дозволу сайту входять до цієї перевірки;
після неї окремо перевіряють розповсюдження через магазин та оновлення.
Для Chrome 0.9.3 вище зафіксовано успішну ручну перевірку зі слів власника:
явно підтверджено Lock двох панелей та імпорт/експорт; точну версію Chrome, ОС,
тип експорту й окремі результати всіх рядків матриці не надано.

## Межі безпеки та випуску

- Використовуйте лише синтетичні секрети, доки ручні runtime-перевірки не
  завершені.
- Установлений ZIP із GitHub не означає схвалення магазину.
- Global Lock відкидає незбережені чернетки інших панелей у пам’яті — спочатку
  дочекайтеся підтвердження збереження. Lock не очищає OS clipboard чи exports.
- Маскування поля не є шифруванням; Markdown, clipboard та exports можуть бути
  відкритим текстом.
- Розширення не є незалежно аудитованим менеджером паролів.
- Перед update або downgrade дочекайтеся **Note saved**, створіть зашифровану
  копію й перевірте пароль до неї.
- Знайдена помилка потребує regression-перевірки, повторної збірки й повторного
  огляду фінального пакета.
